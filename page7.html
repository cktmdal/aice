❓ 7. 결측치와 이상치 처리 (상세 및 데이터 예시)

? 결측치 (Missing Value)

데이터에서 값이 비어있는 경우
예: 기록하지 않아서 확인이 불가한 주문량

처리 방법:

  • 삭제: 결측치가 적을 때
  • 대체: 평균값, 중앙값, 최빈값으로

⚡ 이상치 (Outlier)

일반적인 패턴에서 크게 벗어난 값
예: 평소 50건인데 특정 날 500건

처리 방법:

  • 제거: AI 학습에 방해될 때
  • 유지: 의미 있는 이상치일 때

결측치 처리 방법 구조도

🔤 9. 인코딩 - 문자를 숫자로 변환

🤖 AI는 숫자만 이해해요! '맑음', '흐림', '비' 같은 문자는 숫자로 바꿔야 한다.

레이블 인코딩 (Label Encoding)

순서가 있는 데이터에 사용

배달시간: 빠름 ➡️ 1, 보통 ➡️ 2, 느림 ➡️ 3
고객등급: 일반 ➡️ 1, VIP ➡️ 2, VVIP ➡️ 3

✓ 순서의 의미가 숫자에 반영됨

원-핫 인코딩 (One-Hot Encoding)

순서가 없는 데이터에 사용

날씨: 맑음 [1,0,0], 흐림 [0,1,0], 비 [0,0,1]
요일: 월 [1,0,0,...], 화 [0,1,0,...]...

✓ 날씨/요일 간 우열 관계 없음

⚠️ 잘못된 예 : 맑음=1, 흐림=2, 비=3으로 레이블 인코딩하면?
AI가 '비(3)가 맑음(1)보다 크다'고 오해할 수 있다! ➡️ 날씨는 원-핫 인코딩 사용

⚖️ 10. 스케일링 - 데이터 범위 통일

😟 스케일링이 필요한 이유

기온: -10°C ~ 35°C (범위 45) vs 강수량: 0mm ~ 300mm (범위 300)
AI가 숫자가 큰 강수량을 더 중요하다고 착각할 수 있다.

정규화 (Min-Max)

데이터 범위를 0~1 사이로 변환

공식: (값-최소)/(최대-최소)

기온 25°C ➡️ (25-(-10))/(35-(-10)) = 35/45 = 0.78

표준화 (Z-score)

데이터 범위를 평균 0, 표준편차 1로 변환

공식: (값-평균)/표준편차

기온 25°C ➡️ (25-15)/10 = 1.0
✅ 스케일링 후: 모든 속성이 비슷한 범위를 가지므로 AI가 공정하게 학습할 수 있다.
